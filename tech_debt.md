  2. **Универсальный архитектурный инвариант трейлинга: Геометрия «ПОЛ / КУРОК» в абсолютных величинах:**
      - Если рассматривать абстрактно любую сетку (будь то сетка тейк-профитов или сетка усреднения) в шкале абсолютных величин (`abs()`, модуль дистанции отклонения от точки входа), то вне зависимости от стороны (LONG или SHORT):
        - **ПОЛ (Floor, уровень исполнения, само действие / экзекьютор ордеров)** — **ВСЕГДА НИЖЕ** в абсолютной шкале:
          - *Для тейка:* пол = целевой процент профита (например, 2.0%).
          - *Для усреднения:* пол = глубина отката/уровня для выставления ордера (например, для лонга -8.0%, для шорта +8.0% -> по модулю `8.0%`).
        - **КУРОК (Activation, порог взведения пола)** — **ВСЕГДА ВЫШЕ** в абсолютной шкале:
          - *Для тейка:* курок взводится на более высокой прибыли (например, 3.5% > 2.0%).
          - *Для усреднения:* курок взводится при более глубокой просадке/импульсе (например, для лонга -10.5%, для шорта +10.5% -> по модулю `10.5% > 8.0%`).
      - **Механика отката:** Рынок импульсом преодолевает курок (взведение пола), а исполнение ордера экзекьютором (само действие) происходит **строго при откате цены назад к полу**.
      - **Полиморфизм крайнего уровня (`activation == floor`):**
        Для ВСЕХ стратегий системы, где используется трейлинг, на ПОСЛЕДНЕМ уровне курок выставляется строго вровень с полом (`activation == floor`). При достижении целевой отметки оба условия (`distance >= activation` и `distance <= floor`) выполняются одновременно: происходит мгновенное исполнение действия экзекьютором без ожидания отката.

  3. **Стартовый пул монет боевого бота (Инвариант ручного пула оператора):**
      - Стартовый пул монет задается **СТРОГО ВРУЧНУЮ** оператором в `CFG/app.json` (список `symbols`).
      - Никакого автокомплита монет при старте бота, никакого «прогрева Радара», никаких блокирующих ожиданий. Бот стартует немедленно с тем пулом, который прописан оператором в конфиге (`min_radar_warmup_hours` и блокирующие циклы ожидания полностью вырезаны).
      - Ротация монет срабатывает строго и исключительно в момент автозакрытия позиций автоклозером в 100% кэш (`radar_rotation_on_close` под куполом `auto_closing.positive`).

  4. **Симметричный скор ротации (Score-to-Score) с 35% гистерезисом:**
      - И для воронки Самсонова (`samsonov_funnel`), и для Альфа-селектора (`alpha_coin_selector`) текущие монеты и кандидаты оцениваются строго по единой шкале скора (Score-to-Score).
      - Замена худшей монеты обоймы $W$ на лучшего внешнего кандидата $C$ происходит **ТОЛЬКО** при превышении порога гистерезиса 35%:
        $$\frac{Score(C) - Score(W)}{\max(Score(W), 0.001)} \ge 35\%$$
      - Если отрыв кандидата составляет менее 35%, текущий пул монет удерживает свои позиции (защита от лишних комиссий и частых ложных ротаций).
      - В полигоне (`cron3PapperUniverses`) режим `samsonov_funnel` жестко заблокирован во избежание взаимного дедлока (полигон сам поставляет данные для Радара); полигон использует исключительно `alpha_coin_selector`. По умолчанию в 19 эталонных вселенных полигона `radar_rotation_on_close.enabled = false`, чтобы все 65 монет участвовали в торгах и генерировали полноценную статистику для Радара.

##### Б. «Инвариант уникальности символа на аккаунт» (Account Symbol Isolation Invariant):
1. **Стратегии имеют ОДИНАКОВЫЕ имена ключей (один биржевой счет):**
   - На одном счете Binance позиция по конкретному символу едина. Две разные стратегии физически не могут одновременно вести независимые сетки и слать противоречивые ордера по одной и той же монете на одном счете.
   - Включена **строгая обязательная валидация на непересекаемость символов** в [CORE/STRATEGY/strategy_registry.py](file:///C:/Users/user/Desktop/My_Pro/HP_EliteBook_735_old/MY/HRON_3/cron3/CORE/STRATEGY/strategy_registry.py) и [consts.py](file:///C:/Users/user/Desktop/My_Pro/HP_EliteBook_735_old/MY/HRON_3/cron3/consts.py).
   - Попытка назначить монету `GRASSUSDT` одновременно в `u6` и в `u14` при одинаковом `api_key_name` («API_KEY») немедленно выбрасывает фатальный `ValueError`:
     ```text
     [StrategyRegistry] КОНФЛИКТ В РАМКАХ ОДНОГО АККАУНТА ('API_KEY')! 
     Символ 'GRASSUSDT' одновременно назначен в две стратегии: 'u6_symbiosis_gamma_fortress35' и 'u14_subgrid_level_recycler'. 
     На одном биржевом счете Binance монеты между стратегиями обязаны быть строго уникальными!
     ```
