## 2. ADR Log: Мультистратегический диспетчер и диверсификация торгового ядра (Multi-Strategy Universe Templates)

### 2.1. Контекст и бизнес-цель
* **Контекст**: В боевом боте `cron3` ранее все монеты из списка `symbols` торговались по единому монолитному шаблону `_base.json` (одинаковая сетка, отступы, шаг тейк-профита и логика сигналов). Это исключало возможность портфельной диверсификации.
* **Решение**: Перенос базы из 35 оттестированных стратегий-шаблонов из полигона `cron3PapperUniverses/CFG/universes.json` в `cron3/CFG/universes.json`.
* **Механика**: Внедрение словаря `active_strategies` в `CFG/app.json`. Каждая стратегия имеет флаг активности (`enabled: true/false`) и свой индивидуальный список закрепленных монет (`symbols: ["ARXUSDT", ...]`).
* **Результат**: Боевой бот торгует выбранными монетами по спецификациям назначенных им стратегий, параллельно исполняя разные торговые стили (например, высокочастотный скальпинг `u6_symbiosis_beta_scalper` на активных альтах + консервативный свинг `u0_fat_swing` на тяжелых монетах).

### 2.2. Архитектурные инварианты (Architecture Invariants)
1. **Инвариант 1 (Взаимная однозначность монеты и стратегии - 1:1)**:
   * Каждая торгуемая монета (`symbol`) в один момент времени принадлежит **строго одной активной стратегии**.
   * При старте бот проверяет пересечение множеств символов всех активных стратегий. При обнаружении дубликата выбрасывается `ValueError` (Fail-Fast), предотвращая коллизии ордеров и взаимную перетирку позиций на биржевом счете Binance.
2. **Инвариант 2 (Прямое чтение конфигураций без скрытых дефолтов - Правило 2)**:
   * Секция `active_strategies` читается строго через прямой доступ `_CFG["active_strategies"]`.
   * Отсутствие секции или обязательных полей приводит к немедленной остановке инициализации с понятным исключением.
3. **Инвариант 3 (Принцип None и согласование дефолтов - Правила 2.1, 2.2)**:
   * Все параметры `overrides`, не определенные в стратегии, явно принимают `None` и наследуют базовые значения из `_base.json`. Дефолт `0` категорически запрещен.
4. **Инвариант 4 (Лабораторный минимум Take-Profit >= 0.50% - Правило 11)**:
   * Любой итоговый тейк-профит (`indent`, `fallback_indent`) жестко ограничен снизу `max(0.50, val)` во избежание сжигания депозита на биржевых комиссиях.
5. **Инвариант 5 (Лимиты на размер файлов - Правило 10)**:
   * Модули декомпозируются: реестр стратегий (`StrategyRegistry`), аппликатор параметров (`StrategyApplicator`), менеджеры боевых механик. Размер каждого файла строго в пределах 150–450 строк.

### ADR-2026-09-29: Перенос подсистем Super Grid, Analytics, Notifications и Auto Closing под купола стратегий
* **Контекст**:
  - Ранее блоки `super_grid`, `analytics`, `notifications` и `auto_closing` находились в корне `CFG/app.json` как глобальные настройки, применимые ко всем монетам без дифференциации.
  - По требованию главного Тим Лида («все должно быть под куполами стратегий») произведена полная изоляция и инкапсуляция всех 4 подсистем внутри каждого купола стратегии (`active_strategies`).
* **Архитектурные решения**:
  1. **Купол Аналитики (Analytics Dome)**:
     - Каждая активная стратегия обладает собственным `start_balance_usdt` (по умолчанию 150.0 USDT).
     - Балансы и ROI рассчитываются индивидуально в `ANALYTICS/STATS/analytics_<strategy_id>.json`.
     - Портфельный стартовый баланс `ANALYTICS_START_BALANCE_USDT` суммируется по всем активным куполам (450.0 USDT для 3 стратегий).
  2. **Купол Super Grid (Volatility Manager Dome)**:
     - Параметры адаптивной сетки (`timeframe`, `window`, `multiplier`, `min_volatility_pct`, `max_volatility_pct`, `update_interval_hours`) читаются из персонального купола каждой монеты.
     - `VolatilityManager` модифицирует рантаймы строго по путям куполов `CFG/runtime/<strategy_id>/<symbol>.json`.
     - `avg_manager.py` проверяет активность `super_grid` через купол конкретной стратегии.
  3. **Купол Уведомлений (Notifications Dome)**:
     - `NotifierManager` отслеживает просадки и профициты независимо для каждого купола стратегии по персональным порогам `negative_threshold` и `positive_threshold`.
     - Флаги алертов изолированы в `self.strat_flags[strat_id]`, тексты сообщений маркируются именем и тикерами купола.
